## Как поддерживать эти документы

Документы описывают код **как он есть сейчас**, а не как задумывалось. Если правка
меняет поведение подсистемы — обнови её документ тем же коммитом. Нашёл баг, но не
чинишь — заведи запись в [Известные проблемы](known-issues.md), чтобы он не потерялся.

Каждое утверждение должно быть проверяемым по коду: ссылайся на файл и строку
(`../Assets/Scripts/...`), а не на память. Документ, разошедшийся с кодом, хуже
отсутствующего — ему верят.
