# Бой и здоровье

## StatsHandler — единая модель здоровья

[`StatsHandler`](../Assets/Scripts/UI/StatsHandler.cs) висит на всём, что можно
убить: игрок, боты, враги, постройки, турели.

```csharp
public float maxHP, currHP;
public event Action OnDamage;   // после каждого получения урона
public event Action OnDeath;    // когда currHP упало до нуля
public Fraction fraction;
```

`currHP = maxHP` выставляется в `Start()`.

Всё поведение смерти построено на подписке на `OnDeath`: `Player` спавнит камеру
смерти, `Building` уничтожает себя, `NPCFacade` проигрывает анимацию и убирает
агента, `GatlingGun` уничтожается.

> **Критично:** защиты от повторной смерти нет. Любой урон при уже нулевом HP
> снова поднимет `OnDeath`, и все подписчики отработают дважды.
> См. [Известные проблемы](known-issues.md#p0-2-ondeath-срабатывает-многократно).

## Фракции

```csharp
public enum Fraction { Player, Friendly, Enemy, Neutral }
```

Задаётся в инспекторе на `StatsHandler`. Используется, чтобы зона урона била
только по своим целям.

## Нанесение урона — четыре разных способа

Это главная путаница в боевой системе: урон наносится четырьмя почти одинаковыми
скриптами, которые **по-разному решают, кого бить**.

| Скрипт | Кого бьёт | Урон | Как выбирает цель |
|---|---|---|---|
| [`DamagePlayer`](../Assets/Scripts/Enemy/DamagePlayer.cs) | игрока | 10 | по `fraction == Player` |
| [`DamageBot`](../Assets/Scripts/Enemy/DamageBot.cs) | ботов | 5 | по `fraction == Friendly` |
| [`DamageEnemy`](../Assets/Scripts/DamageEnemy.cs) | врагов | `botDamage` | по наличию компонента `Enemy` |
| [`DamageZombie`](../Assets/Scripts/Player/DamageZombie.cs) | врагов | `damage` | по наличию компонента `Enemy` |

Все четыре работают через `OnTriggerEnter`: это коллайдеры-триггеры на оружии или
на теле врага, срабатывающие в момент касания.

Проблемы, которые отсюда следуют:

- **Два критерия вместо одного.** Половина скриптов смотрит на фракцию, половина —
  на тип компонента. Враг с `fraction = Enemy`, но без компонента `Enemy`,
  неуязвим для оружия игрока.
- **Урон зашит в код** у `DamagePlayer` и `DamageBot` (10 и 5) — не настраивается.
- `DamageEnemy` и `DamageZombie` отличаются только типом поля урона
  (`int` против `float`).
- Урон идёт по факту **входа** в триггер, без учёта анимации удара и без
  перезарядки — зажатый в цели враг наносит урон один раз и больше никогда,
  пока не выйдет и не войдёт снова.

План объединения — в [Архитектурном плане](architecture-plan.md#этап-6-бой-и-ии).

## Турель

[`GatlingGun`](../Assets/Scripts/AI/GatlingGun.cs) — автоматическая защита базы.

Как работает:

1. В `Awake` подгоняет радиус `SphereCollider` под `firingRange`.
2. Раз в секунду `ScanForTarget()` ищет ближайшего `Enemy` в радиусе через
   `Physics.OverlapSphere`.
3. `AimAndFire()` каждый кадр: доворачивает основание и ствол на цель, крутит
   стволы, запускает `muzzelFlash`, и раз в `fireRate` секунд наносит `damage`.
4. На смерть цели подписывается `CheckTarget`, чтобы сбросить её и прекратить
   огонь.

Особенности:

- Стрельба **без луча и без препятствий** — урон наносится напрямую по цели, стены
  не защищают.
- Поле `stats` публичное, но перезаписывается в `Awake` через `GetComponent` —
  значение из инспектора не имеет смысла.
- `BuildTower()` инстанцирует **сам себя** в точке с тегом `BuildingPoint`;
  выглядит как отладочный метод.
- Подписка/отписка от `OnDeath` целей сделана вручную и разъедется, если цель
  уничтожат не через смерть (например, при выгрузке сцены).

## Дрон

Стрельба дрона описана отдельно — см. [Дрон](drone.md#стрельба). Там урон наносится
**лучом** (`Physics.Raycast`) по траектории лазера, с тиком `interval`, и ищет
`Enemy`/`StatsHandler` вверх по иерархии от попадания. Это самая аккуратная из
боевых реализаций в проекте — её стоит брать за образец при объединении.

## Отображение здоровья

| Скрипт | Чем показывает | Где |
|---|---|---|
| [`CanvasController`](../Assets/Scripts/UI/CanvasController.cs) | `Image.fillAmount` | мировой Canvas над NPC |
| [`PhpBarController`](../Assets/Scripts/UI/PhpBarController.cs) | `Slider.value` | тоже uGUI |

Оба подписаны на `OnDamage` и пересчитывают долю `currHP / maxHP`. Оба — на старом
uGUI. `CanvasController` дополнительно разворачивает Canvas к камере и прячет его
дальше `visableDistance`.

> Имя `PhpBarController` — опечатка, имелось в виду «HP Bar».
